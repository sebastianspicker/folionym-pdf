How it works

Folionym takes the text layer, or runs OCR on scans, and finds the date, document type, sender, and amounts.

Rules and a model you choose (any OpenAI-compatible endpoint, local by default) suggest the category, keywords, and summary.

Tick the names you want. Apply checks that each file is unchanged and the target is free, then renames it.

Safety checks

Preview changes nothing

Preview builds a plan. Files are renamed only when you apply.

Uncertain names are flagged

When the evidence is thin, the name is marked Review and the reason is shown.

Apply re-checks each file

A changed source or an occupied target stops that file instead of renaming it.

Runs on your machine

With a local model or --no-llm, no document text leaves your computer. External endpoints need confirmation.

Install

Python 3.14 or later. Install from a clone of the repository; the pdf extra adds PyMuPDF. OCR and a model endpoint are optional.

FAQ

Does document text leave my computer?

Only if you point it at an external model endpoint or set up a post-rename hook. With a local endpoint or --no-llm, everything stays on your machine.

What if a file changes after Preview?

Browser and directory-TUI Apply re-check each source and target. A changed source, duplicate target, or occupied name fails instead of being renamed.

Can I undo a rename?

Record a log with --rename-log and run folionym-undo. It reverses safe same-directory moves whose target still exists and whose original path is free.

Does the demo read my files?

No. The demo runs in your browser on simulated documents. It reads no PDFs, calls no backend, and renames nothing.

Which names does it produce?

By default YYYYMMDD-category-keywords-summary.pdf. Templates can also use project, version, invoice ID, amount, and company fields.
